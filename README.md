# 坦克大戰 — Battle City (HTML5)

純 JavaScript + Canvas 的坦克大戰重製版。**無框架、無建構步驟、無任何圖片或音訊檔案**：戰場地形由 `js/mapgen.js` 程序化產生（255 張，依地圖編號固定）、所有貼圖與音效都是開機時程序化產生的。

內含兩種玩法：**單人闖關**（關卡無限延伸，第 n 關用地圖編號 `(n-1) mod 255`），以及不用自己上手的 **A.I. 對戰觀戰模式**（兩隊 AI 各守自家老鷹互打）。觀戰模式的 AI 可以是手寫規則，也可以是**訓練出來的 NEAT 網路**——先用模仿學習讓網路學會規則 AI 的基本動作，再逐段演化（今天 100 場、明天接著跑），訓練成果與「每一局怎麼打」的過程數據都能在 `ai/monitor.html` 看到。

## 遊玩方式

直接用瀏覽器打開 `index.html` 即可（`file://` 就能跑，不需要伺服器，也不用安裝任何套件）。

```
開場：按 Enter 開始單人遊戲 ／ 按 T 進入 A.I. 對戰觀戰
```

## 操作

| 按鍵 | 功能 |
| --- | --- |
| `W` `A` `S` `D` 或方向鍵 | 移動 |
| `J` 或 `空白鍵` | 射擊 |
| `P` | 暫停／繼續 |
| `R` | 重開本關（觀戰模式中＝重打本輪） |
| `Enter` | 開始／回標題 |
| `T` | 在標題畫面進入 A.I. 對戰觀戰（兩隊都是規則 AI） |
| `Y` | 在標題畫面進入觀戰：藍隊＝訓練好的 NEAT 網路、紅隊＝規則 AI |
| `U` | 在標題畫面進入觀戰：兩隊都用同一份訓練基因組（自我對弈） |
| `M` | 靜音切換 |

## 單人模式

守住下方的老鷹，殲滅每關 20 台敵軍（場上同時最多 4 台）。老鷹被命中、或生命扣完即結束。

**地形**

| 地形 | 特性 |
| --- | --- |
| 磚牆 | 可破壞，以 8×8 的最小格逐塊削除 |
| 鋼牆 | 只有火力 L4 能打破 |
| 水面 | 擋坦克，子彈可穿越 |
| 樹叢 | 可通行，會蓋住坦克（畫在最上層） |
| 冰面 | 可通行但會打滑，放開按鍵仍繼續滑行 |

**敵軍種類**

| 類型 | 血量 | 速度 | 子彈 | 分數 |
| --- | --- | --- | --- | --- |
| 輕型 | 1 | 慢 | 一般 | 100 |
| 裝甲車 | 1 | 快 | 一般 | 200 |
| 速射 | 1 | 慢 | 快速 | 300 |
| 重型 | 4（變色：綠→黃→橘→白） | 很慢 | 一般 | 400 |

**火力等級**（吃星星升級，死亡後歸零）

- `L1` 基本 → `L2` 子彈加速 → `L3` 同屏兩發 → `L4` 可破鋼牆

**道具**（由「閃紅」的敵人被擊殺時掉落，或觀戰模式下定期出現）

| 道具 | 效果 |
| --- | --- |
| 星星 | 火力升一級 |
| 炸彈 | 全滅場上敵軍 |
| 時鐘 | 凍結敵軍 10 秒 |
| 鏟子 | 老鷹周圍磚環暫時變鋼牆（20 秒） |
| 護盾 | 無敵 10 秒 |
| 坦克 | 多一條命 |

**其他規則**：每 20,000 分獎勵一條命；每關第 4、11、18 台出場的敵人是閃紅（掉道具）；最高分存在瀏覽器 `localStorage`（key：`tankBattleHiScore`）。

## A.I. 對戰觀戰模式（按 `T`）

兩隊全程由 AI 操控，你只需要看。左右兩欄是三個獨立區塊（`js/hud.js`）：**① 訓練狀態**（場上這顆大腦是第幾代、訓練端有沒有在跑）、**② 紅藍隊伍＋倒數**（兩隊各自的出兵／擊殺／分數／老鷹與 30 秒計時）、**③ 用滑鼠操作**（暫停／重開／下一輪／速度／換圖／換模型，全部可點，不必碰鍵盤）。

- **直立長戰場（v9）**：戰場是 **9:21** 的 18×42 cells（144×336 邏輯 px），畫布位圖 288×672（`SCALE = 2`），頁面依視窗高度用 CSS 把它放大到 672～1344 px——**不放大位圖**，貼圖才不會糊（`SPRITE_SS` 恆為 2）。代價是兩隊家門口之間的直線距離從 184px 變成 312px，所以 30 秒倒數內「攻不攻得進去」跟正方形時代不是同一件事——**這個不靠直覺，量過了**：`node measure-breach.js 120`（120 局、每局一張不同的隨機地圖、兩席都是規則 AI）實測 `breach 25/120 = 20.8%`、`time 70/120 = 58.3%`、`counter 25/120 = 20.8%`，破局那 25 局的中位數是 1,297 幀（約 21.6 秒），最快 443 幀、最慢 1,870 幀（含開場 ~70 幀前置，倒數從那之後才開始計）。所以新戰場上「拖時間」變容易了，防守方仍然有 79.2% 的勝率——**倒數秒數暫時不動**，先把 v9 的尺穩定下來讓網路學「312px 要怎麼走完」，等訓練端冠軍的 `breach` 比率出來再決定要不要放寬時鐘（放寬＝換尺，會再觸發一次重評）。
- **同一把尺重量過（批次四之後）**：上面那組 20.8% 是 v9 時代、規則 AI 還沒角色化也沒有火力節拍時的讀值。同一支 `node measure-breach.js 120`（120 局、每局一張不同的隨機地圖、兩席都是規則 AI）在批次四之後重跑：`breach 40/120 = 33.3%`、`time 55/120 = 45.8%`、`counter 25/120 = 20.8%`，破局那 40 局中位 1,068 幀（約 17.8 秒）、最快 347、最慢 1,725 幀；紅隊取勝從 79.2% 降到 66.7%。結論是「攻得進去了，但時鐘仍是多數」，**所以倒數秒數依然不動**——現在不動的理由跟當時不同：當時怕的是「尺度還沒學熟」，現在是「已經偏進攻了一點，放寬會再偏一次」。這組數字同時也是 `rule` 這個對手標籤底下悄悄換尺的證據（見上一節末尾那條 ⚠）。
- **每輪隨機、但可重現的地形（v9）**：255 張戰場由 `js/mapgen.js` 依地圖編號生成——`mapId → 固定種子 → 固定地形`，所以「隨機」是指「這一輪換一張圖」，不是「每次開頁亂到不知道哪裡」；同一張編號在任何機器、任何時間都長得一樣，訓練分數才可比、`R` 重看剛剛那一場才有意義。想要不一樣的戰場就換編號（右欄 ◀▶／「🔀 每輪隨機」）。
- **兩隊面對的幾何完全等價**：產生器只生成上半部，下半部做 **180° 點對稱**鏡像（`cells[41-y][17-x] === cells[y][x]`，逐格成立、共 756 格），中央那一排另外強制左右對稱並留一條橫向通道。⚠ 鏡像必須在 **tile** 級做：在 cell 級鏡像會切出 8px 的半塊牆，坦克 16px 走不過去，看起來就是「莫名的一小塊磚」。
- **每一台車都真的有路可走**：開局前對每個出生 tile 跑一次 tile 級 Dijkstra，走不到「敵方要塞外側那一排」就沿最便宜的路徑挖開（優先挖磚，其次鋼／水；老鷹與要塞牆列為禁挖）。不挖的話，隨機地形會（少見但必然地）長出「把敵方要塞整個圍死」的圖——那種局只有 `time` 一個結果，觀戰變成看兩隊在自家門口繞圈，訓練端還會把「攻不進去」誤學成「防守很好」。
- **各守各家**：藍隊守下方老鷹、紅隊守上方老鷹（上方那隻旋轉 180°）。每隊各有 20 台坦克池，場上同時最多 4 台（`js/constants.js` 的 `DEMO_MAX_ON_FIELD`），從自家底邊出生。
- **開場就 4 對 4（v8）**：一輪開始時兩隊各一次派出 4 台、站滿自家四個出生點，之後才改成「打完才補、補到 4 台」。之前是第 20 幀擠出第一台、每 100／150 幀補一台，所以開局常有「一邊兩台、另一邊一台」的瞬間——那是出兵節奏，不是戰況，卻會被直接當成戰況看。現在第一幀就是 4 vs 4，兩隊同幀、同一樣的四點，不會偏袒任何一席。⚠ 這改的是**戰場**而不是算式，分數卻因此不可與 v7 直接比（見下方算分版本）。
- **開局從老鷹旁出車**：每輪第一台車固定從自家老鷹左右兩側的中央出生點（x=64/128）對稱出現，逐輪換邊；其餘三台才用四點隨機。這樣開局不會再看到「一台在地圖最左、一台在最右」的邊角畫面。這只是觀戰頁的展示調整，訓練競技場仍用原本的四點分佈，分數不受影響。
- **藍＝進攻、紅＝防守（v6 規則）**：藍隊唯一的贏法是 **30 秒內打爆紅隊老鷹**；拖滿 30 秒、或兩隊兵力池都耗盡，一律算紅隊贏。紅隊另有「反守為攻」：打爆藍隊老鷹也算紅隊贏。所以場上不會再出現「兩邊都只想守、拖到時間比積分」的局。
- **不準朝自己要塞開槍（v6 彈道閘）**：每次要開火前，先沿槍口方向一格一格走一遍彈道——只有磚與鋼會擋子彈，水跟樹林不擋。第一個擋下來的是自家老鷹或自家要塞牆 → 這一槍收手；是一般磚牆、或根本飛得出界 → 放行。規則 AI（`js/ai.js` 的 `_ownBaseInFront`）與訓練網路那端（`ai/controller.js` 的 `ownBaseInFront`）用同一套幾何判斷，兩邊不會各判一套。
- **自己打爆自家老鷹要記帳（v7）**：該隊這一局直接記 **0 分**（計分的地板，不是扣分——扣分可以用別的項補回來，那就不叫避免自破），對面也拿不到勝負分，因為那不是它打出來的。結算畫面與 ② 欄會標「⚠ 自破：X 隊把自己的老鷹打爆」，訓練端另記 `ownBaseKilledBySelf`／`foeBaseOwnGoal` 兩筆計量。
- **貼身就先解決對方坦克（v7）**：敵車中心距小於 40px（`AI_DUEL_RADIUS`）時，最高優先目標從「回防／追擊／衝基地」改成**那台敵車本身**，同時把節奏換掉：重新決策 40～100 幀 → 8 幀（`AI_DUEL_REPICK`）、同軸命中率 0.55 → 0.9（`AI_DUEL_SHOOT`）、射擊冷卻 25～75 幀 → 8～15 幀。貼身造成的擊殺另外記一筆 `duelKills` 並計分。
- **AI 行為（沒有貼身敵車時）：席位決定目標（批次二＋批次五 J）**：規則 AI 原本對兩隊是同一支碼（40% 追敵、30% 打老鷹、其餘巡邏），所以「誰是進攻方」只寫在規則與計分裡，行為層完全沒反應——探針量到紅隊（防守）也一路追到藍隊門口，兩隊在對方半場停留的時間差不到 3 個百分點。現在 `_goal` 依席位分岔：敵車壓到自家老鷹牆腳（56px，`DEMO_THREAT_RADIUS`）時兩席都先回防；防守席再往外攔到屏蔽半徑（112px ≈ 場高 1/3，`DEMO_SCREEN_RADIUS`），沒威脅就站在自家門前 56px 那條防線上橫向散開，**絕不一路追到對方門口**；**進攻席（批次五 J，收斂後）的位移只認對方主堡**（`assault`；門檻常數 `AI_ASSAULT_RADIUS`＝56px，直接沿用牆腳那把尺），「先打敵車」這句話落在**射擊層**、不是位移層。⚠ 初版把它寫成「位移預設去追場上最近的活敵車（`hunt`）」，同一支 240 局的尺實測把進攻席破局率從 **31.7% 拉到 18.3%**；縮小追車範圍救不動——只排「擋在去主堡路上」那台 18.3%（跟不縮一樣＝標準誤差 ±3.2% 之內），再放寬到「過中線或距自己 ≤168px」20.4%，只有**位移完全不追**回到 **31.7%**（五檔同一組考題並排見 `node audit-hunt.js 240`）。原因不是「打車不對」：hunt 的目標點每 8～100 幀就換一台車，而攻城要的是 300 幀級的穩定方向——實測多殺 0.6 台（5.9 → 6.5）賠掉 13 個百分點的本業，是「用射擊的邏輯去開車」。附帶的好處落在平衡度上：同一輪量到的兩席均分比從 1.95×（無限追）收到 1.10×（現行），也就是兩族「起步」拿到的分數終於同一個等級（這條主軸見 BALANCE-RESEARCH.md）。追車只留兩條既有例外：敵車壓到**自家**牆腳 ≤56px 一律回防、貼身 ≤40px（`AI_DUEL_RADIUS`）先解決那台；位移層那支追車碼（`_nearestLivingFoe`）已經整條刪除，有測試釘住（「拿回來就會賠破局率」這件事因此查得到，不靠記憶）。開火選靶仍走「先車後堡」（`_shotTarget(tank, game)` → `'tank'`／`'base'`／`null`）：同軸前方有活敵車就打車（就算主堡也在同一條線上），同軸只有主堡**而且已貼到門口**才打堡，否則這一槍不開——舊版那種「對著 300px 外的老鷹慢慢開槍」沒了。批次二那條「擋住走廊 64px 內（`AI_BLOCK_REACH`）的敵車 32% 機率先清障（`AI_ATTACK_CLEAR_SHARE`）」**整條刪除**（不是留著當第二套預設）：它跟新的選靶順序會同時存在、互相蓋，跟批次四刪掉 `_laneDir` 是同一個教訓。單人模式的敵人 `role=null`、也沒有自己要塞，走原本那套擲骰，行為不受影響。⚠ 換了老師＝`rule` 這個對手標籤底下換了尺（見下方算分版本那節與 `BALANCE-RESEARCH.md` §5.8）：同一支 `node measure-breach.js 120` 讀 **批次四 33.3% → 初版（追車在位移層）22.5% → 現行（不追）29.2%**，訓練端往門口推的訊號仍在 `breach`（70 分）＋`besiege`＋v11 的近距離拆牆那三項上。
- **開火節拍跟著「家裡有沒有事」（批次四）**：防守席舊版一局只開 16.2 槍，同一席換成純隨機按鍵反而開 198.7 槍、擊殺更多、連勝率都更高（16.2 槍的根因：原地轉是違法的，同軸時機本來就少，再被 25～75 幀的平均 50 幀冷卻稀釋 → 那門炮是裝飾）。現在每次開火前先問「敵車離我家多近」，分四級排節奏：貼身（duel）8～16 幀、敵車已到屏蔽圈（screen）10～20 幀、敵車在自家半場（home）16～30 幀、都沒事（idle）維持原本 25～75 幀。擲骰也分級：同軸非格鬥 0.55 → **0.8**（`AI_LINE_SHOOT`）、貼身 0.9，不同軸時 screen 留 0.15、home 留 0.08 的壓制機率（封走廊、逼對方讓路），idle 仍是 0.04。**沒有改成必中**——打不打得中正是 `accuracy` 那一項在量的東西，必中等於把計分項的訊號自己抹掉。實測：規則 AI 坐紅席每局開火 16.2 → 30.6 槍（同一組 24 局考題、`--mode ladder` 的 p=0 那一格，前後都是 v10 尺），96 局放大版讀 31.0，測試自己的 12 局考題讀 28.8（三個讀值是不同考題上的同一件事）；坐藍席 28.3 槍／局（節拍不是只為防守改的）；同一席換成「每幀都亂按但守紀律」的對照組（ladder 的 p=1，96 局）是 190.7 槍／局。⚠ 對照組要用那支混合控制器，**不能用 `arena` 的 `'random'`**：那是 `randomPolicy()`，每幀自己選方向、15% 機率開火，而且不經過 v6 那一道彈道閘，所以下場就把自己的老鷹打爆（實測 16/16 局自爆、防守分整臂 0）——它量的是「自爆」，不是「不會打」。⚠ 另外，這改的是**老師**，對戰紀錄裡的 `rule` 標籤沒變、尺卻變了，所以批次四前後的分數不可直接比（見下方算分版本與 `BALANCE-RESEARCH.md` §5.7）。
- **不會原地磨蹭**：所有 AI 坦克（規則 AI 與訓練網路都一樣）的轉向必須伴隨位移；往前走得通時不準下一步直接原路退回；轉向後還要連走 12 幀（約 1～2 格）才準再轉，期間只準繼續往前，不準每幀換垂直方向。所以看不到「原地左右翻面」、「上下抖動」或貼著牆兩格之間高速鋸齒——要掉頭得先走一步垂直方向，或等前方真的被擋住。玩家坦克不受此限，貼牆轉向仍是正常操作。
- **道具歸 AI 使用**：誰先撞到誰生效——升級火力、開護盾、凍結敵隊、炸光敵隊、把自家磚環鏟成鋼牆、或替自己隊伍補一台車。
- **自動續戰**：結果畫面停留 5 秒後自動開下一輪，並**隨機抽一張地形**（255 張隨機地圖；同一張編號在任何機器上長得一模一樣），可以一直擱著看。想反覆看同一張圖就用右欄的「🔀 每輪隨機／📌 固定這張圖」切換鎖定，再用 ◀▶ 瀏覽地圖編號（HUD 顯示「地圖 N/255」）。

## 會變聰明的 AI（NEAT 自進化）

觀戰模式裡的 AI 有兩種來源：**規則 AI**（`js/ai.js`，手寫的 if-else）與**訓練 AI**（用 NEAT 演化出來的類神經網路）。訓練分兩段：先用模仿學習把規則 AI 的行為複製進網路，得到一個「一開場就會開車」的種子，再讓 NEAT 從種子往上進化；過程是**逐段累積**的——今天跑幾百場、把族群落盤，明天從同一個檔案接續，網路一代比一代強。每一輪都能用 `ai/monitor.html` 看到它「怎麼打」而不只是「誰贏」。

### 第 0 步：先用規則 AI 的資料暖啟動（強烈建議）

從隨機權重開始演化，第一代就會「動」（⚠ 不是「躲在規則 AI 後面不動」——這個機制量過，見本節末尾），但動的方向是亂猜的，那段期間最容易掉進「卡牆掃射」這種結論好看、過程是壞的局部最優。所以管線的起點不是隨機，而是**把規則 AI 的行為複製進網路**：

```bash
# 1) 收示範：規則 AI 打幾局，記錄每幀的（觀測 → 決定），依事件加權取樣
#    （卡牆轉向、自由轉向、老師開火、有射擊線、繼續走 五類分開控管）
node ai/imitate.js --stages 0,1,2 --games 3 --out runs/seed.json
#    → runs/seed.json（模仿種子）＋ runs/seed.genome.json（給網頁/監測看的基因組）

# 2) NEAT 從這份種子往上進化（族群全部由它變異而來）
node ai/evolve.js --seed-from runs/seed.json --gens 80 --pop 24 --stages 0,1 --seeds 2 --out runs/warm.json
```

種子本身（第 0 代、還沒演化過）就已經會「正常開車」：卡牆 0.1%、在場幀 99.9% 由網路自己決策（現行尺下 `node audit-coldctrl.js` 印的就是這一列，旁邊還有老師與隨機權重的對照）。**但它買到的只是過程，不是勝負**：把種子放進自己席位、對手恆為規則 AI，現行碼實測（每席 24 局，數字印在 `node test-train.js` 的 W 節 testName 上）是**進攻席 0 勝／0 破局**，而同樣坐那席的老師破得了 25%（8 局考題，兩個數都由測試現量並印在名字上）——逐幀忠實度 88% 學得會「這一步轉向／這一刻開火」，學不會「那條 312px 的走廊要一路走完」，這是行為複製的天生上限，不是尺壞。

⚠ **種子會過期，而且過期不會報錯**：`js/ai.js`（＝老師）一改，舊種子複製的就是上一代老師的行為，檔案裡的 `generatedAt` 是唯一線索（批次五之前就帶著 11-02 10:20 收的種子跑了整個批次）。改完老師要重收：`node ai/imitate.js --role attack --out runs/seed-attack.json`／`--role defense`；舊種子先存成 `runs/seed-*.pre-batchN.json` 再覆蓋，才比得出前後差。⚠ 重收後第一代可能**更低**（防守 19.3 → 10.7）——那不是收壞了，是新老師更難模仿；也別順手把 W 節「暖啟動 N 代冠軍要打得過規則 AI」那個門檻調低（N＝5 是 v12 換尺時重量過曲線定的，v13 再跑一次仍是 5 代、門檻沒降，理由與實測曲線見下面算分版本那節）——它量的是演化有沒有把過程變成勝負，跟種子高低無關。

⚠ 順帶更正一句流傳了幾個批次的舊解釋（「冷開機第一代很多幀在 abstain、由規則 AI 代步，所以它的 mean 天生虛高」）：**量過是錯的**，隨機權重的控制權就有 99.8～99.9%（abstain 要「最大輸出 < −0.85」，而隨機 argmax 幾乎永遠在上面）。冷開機第一代 mean 偶爾比暖啟動高，是因為**亂走也會撿到過程分**（防守席某隻隨機基因組 87.35 ＞ 老師 55.87 ＞ 種子 22.61）。所以「第一代 mean 誰高」不能拿來論暖啟動划不划算——要判斷劃不划算，看暖啟動 5 代冠軍坐回席位的勝負（`test-train.js` W 節；v12 之前這個數是 3 代，換尺後重量過，見算分版本那節）；而「零技能不該拿到本業分」這一半還沒做完，記在 `BALANCE-RESEARCH.md` §5.8。

`--seed-from` 只接受 `ai/imitate.js` 的種子檔；拿匯出的基因組冒充種子會被拒絕（創新號是另一本帳的號碼，硬塞會讓交叉認錯邊）。

### 訓練（純 Node，不需要瀏覽器）

```bash
# 今天：跑 20 代（族群 24 × 3 張地圖 × 2 種子 × 雙座位 = 288 場/代）
node ai/evolve.js --gens 20 --pop 24 --stages 0,1,2 --seeds 2 --out runs/neat.json

# 明天：從上次落盤處接續，這次只跑 3000 場（能跑幾代算幾代）
node ai/evolve.js --resume runs/neat.json --episodes 3000

# 看成果：收斂曲線 + 對規則 AI 的實戰勝率（用沒參與評估的新種子）
node ai/evolve.js --report runs/neat.json

# 過程監測：逐幀數據 + 紅旗，並寫出 ai/monitor.html 要的資料
node ai/monitor.js --ckpt runs/warm.json --stage 0 --games 4

# 匯出冠軍給瀏覽器：寫出 ai/trained.json 與 ai/trained.js（單模型舊路徑，留給手動比對）
node ai/evolve.js --export runs/warm.json

# 或者：練完直接幫瀏覽器換快照（少這一步，網頁會一直停在舊快照）
# 現在是雙模型，快照要寫到「該角色」那一份，否則觀戰那隊讀不到
node ai/evolve.js --resume runs/attack-v6.json --gens 20 --export-to ai/trained-attack.json
node ai/evolve.js --resume runs/defense-v6.json --gens 20 --export-to ai/trained-defense.json
```

`--gens` 與 `--episodes` 至少要給一個（都沒給會無限演化，CLI 直接拒絕啟動而不是卡住）；兩個都給時取較嚴的那個，但場數不足一代時仍會把一代跑完。`--opponent rule|random|best` 換對手，`best` 等於跟目前的冠軍自我對弈。其他：`--pop`、`--stages 0,1,2`、`--seeds N`、`--save-every N`、`--seed N`、`--quiet`、`--max-frames`。續練時 `--stages` 是「明確換考題」，用法與後果見下面〈續練時加入沒練過的地圖〉。

### 「我玩了很多場，數字怎麼都沒增加？」

因為**觀戰不訓練**。`ai/trained-attack.js`／`ai/trained-defense.js` 是訓練成果的**快照**：裡面的「第 N 代／適應度／累計場數」是訓練端最後一次匯出時寫進檔案的數字，瀏覽器不會回寫任何東西——網頁上沒有梯度、不落盤、也不存檔。

但現在有**自動跟隨**：觀戰開始後每 12 秒用 cache-buster 重讀一次那兩份快照。訓練端若用 `--export-every 1` 每代刷新（`ai/auto-train.js` 預設就是），左欄 ① 的代數與快照時間會自己往上走，任一族的冠軍換人時場上該隊的車直接換網路，**不必重新整理**。只有「訓練中斷、頁面還停在上一次載入的舊 JS」這種跨版本情況才需要 F5 一次。

① 那塊的值欄只放「場上這顆大腦是第幾代、拿幾分」，訓練練到第幾代、快照幾時匯出、評這個分數時對面是誰 —— 全部收在滑鼠提示（title）裡。原因是全站最小字級 16px（值欄 17px），320px 的面板扣掉標籤欄與 padding 一行只塞得下約 17 個全形字，硬塞會折行、數字反而看不出來。

最後一行「本機累計已看 N 輪」存在 `localStorage`，跨重新整理會累加（所以它是「這台電腦累計」，不是「這一頁」），但那只是本機計數，跟 AI 變不變聰明無關。

要讓分數真的上去，只有跑訓練這一條路——最省事就是下面的全自動模式。

⚠ **算分版本換了，分數就換了單位**：v1 → v2 修好「致命一擊不計入傷害」；v3 加入防守與協同兩項；**v4 的公式沒改，但對手變了**——規則 AI 不再於死角原地旋轉（`js/ai.js` 的 `_pickDirection` 四面堵死時維持原向）。以前那幾幀是白送給網路的空檔，修掉後同一個對手更難打；**v5 又把防守擴大到自家半場**，並讓所有 AI 的移動都加上「轉身必須有位移、走得通就不準立刻原路退回」的限制。

**v6 把「誰該做什麼」寫進規則**：藍＝進攻、紅＝防守，30 秒未破局由紅隊取勝，於是進攻族與防守族第一次有了各自的考題，TERMS 也分成 `attack`／`defense` 兩套（同一份報告、兩種算法）。**v7 加兩條使用者規則**：`ownEagleBySelf`（−80，外加「自破那局總分歸 0」的地板）與 `duelKill`（+8，每局最多計 4 台）。同時把 breach／holdWin／holdGate／speed 那幾項從 `won` 改讀 `winByMerit` —— 否則「等對方自己把老鷹打爆」會變成兩邊共同的最低努力解。v3～v7 彼此的分數都不能直接比。

**v9 改的還是戰場，而且一次改兩件事**：形狀從 26×26 正方形換成 **18×42 cells 的 9:21 直立長場**，地形從 35 張手刻關卡換成 **255 張隨機生成**（`js/mapgen.js`，同一張編號在任何機器上長得一模一樣）。量程變了就得換尺：進攻方從自家底邊到紅隊老鷹的直線距離由 184px 變成 312px，`penetration` 用的半場尺（`HALF_FIELD_PX`）跟著從 104 換成 168（＝`FIELD_H / 2`）；算式與權重一樣沒動，所以 v8 的冠軍照例在新考題下重評（8 場校準局，不計入訓練場數）。

⚠ 這一版**刻意沒有**升感測器規格（`ai/observation.js` 的 `OBS_SPEC` 仍是 v2／85 欄）：升版會讓五個載入點硬擋掉已經練到 ~1,970 代、37 萬場的那兩條 checkpoint，等於把「越玩越聰明」歸零。代價是座標歸一化仍用舊的 104／208，所以 y 現在可能超過 1——那是網路要重新習慣的**分佈偏移**，不是算分錯誤；下一波從零重訓時才適合把 `OBS_SPEC` 一起換掉。

**v8 改的是戰場，不是算式**：開場每隊一次出滿 4 台（上面那條「開場就 4 對 4」）。權重、地板、`TERMS` 逐項說明都沒動，但量測的戰場換了——場上同時多一倍的車，推進、攔截、貼身、開火密度全部重新分布，同一隻網路在 v7 拿 58.12 分、v8 重評只剩 3.67 分（防守族）／97.61 → 41.64（進攻族）。**換版的原因寫在 `ai/fitness.js` 的 `SCORING_VERSION_NOTE`**，履歷與看板的「算分 vX→vY」接縫就是從那裡讀出來的，不是另外編的說明。

**v10 把兩席的「起步平衡度」重新配平**（研究過程與實測數據在 `BALANCE-RESEARCH.md`，探針是唯讀的 `ai/balance.js`）。動機不是分數不好看，而是探針量到**本業項與交戰項的比例歪了**：擊殺效率、傷害、準度這一類「兩席天天都會發生」的項，天花板加起來比一方真正的本業還高，等於演化可以靠拈著便宜項得分、不必學會攻城或守門。改動分三組：

- **壓交戰項**：`killPer1k` 權重 9→4.5、上限 40→24，`damagePer1k` 3→1.5，`duelKill` 8→6（上限 4 台），另有 7 項一起往下壓，讓通用項總和落回本業之下。
- **補本業項**：進攻新增 `besiege`（壓在敵鷹門口的占比，滿分 `BESIEGE_FULL=0.15` 給 30 分——之前「圍而不打」一分都拿不到，於是只能靠擊殺補）；防守新增 `denial`（把對手擋在自家半場之外，`DENIAL_ZERO=0.55`→`DENIAL_FULL=0.25`，而且要打掉 ≥`DENIAL_PROOF_HP=4` hp 才算證明，32 分）；`holdWin` 從一個 45 分拆成「撐到時鐘 18」＋「打掉敵鷹 45」，避免兩種完全不同的勝利拿同一份錢；`timeoutFail` 由固定 −25 改成按實際推進程度打折（打到敵鷹門口 84px 只扣一半）。
- **第三項嘗試過、量過之後刪了**：`screenHold`（門前在場 20 分）。48 場實測顯示**隨機按鍵的門前占比（28.0%）比規則 AI（14.8%）還高**——在家門口繞圈就能領薪，那不是本業是反技能。同一個教訓用在 `holdGate` 的重設計上：門檻 6hp→2hp，「門前在場占比」從**加法**改成**乘法加成**，零攔截光站位一分都不給（34 分裡佔一半的 17 分要有實際擋下的傷害才拿得到）。
- **把兩席的本業上限拉到同一高度**：家門口攔截 30→35、半場攔截 20→24，防守本業由 173 補到 195.7，進攻本業 189.5（`node ai/balance.js --mode ceiling` 印的是這份單一來源，不是另外算的）。`GATE_HP_FULL` 6→5、`HALF_HP_FULL` 新增為 6，兩項都各有上限，防止「同樣的傷害重複計價」。

⚠ 換尺的代價照例要誠實標出來：v9 的冠軍在 v10 上重評，舊防守冠軍只有 64.73（同場規則 AI 基準 63.24），舊進攻冠軍 163.76 —— 這不是變弱，是**舊冠軍原本就是在舊尺下被選出來的**。所以驗收指標裡的「換上模型加分比 ≤2×」（③）在這一步必然過不了，它量的是冠軍成熟度、不是新尺好不好，要等交替演化把兩族都拉到新尺上重新跑熟（#70 的重啟就是為此）。

⚠ **批次四（火力節拍）改的是老師，不是算式——`SCORING_VERSION` 仍是 10，所以「換版接縫」不會自己標出來。** 上面那條偵測只認 `scoringVersion` 一個數字，但真正會改變分數單位的有兩件事：算式，和**被測的那支碼**。同一組 24 局考題（`--mode ladder` 的 p=0 那一格，v10 尺沒動）在節拍改前後讀到：老師每局開火 16.2 → 30.6 槍、擊殺 6.63 → 7.75、卡住幀 184.0 → 144.7，可**均分只從 63.97 走到 66.98**——行為動了一倍、分數幾乎沒動，這正是「用分數變化偵測不到換尺」的那種改變。防守席的勝率甚至從 75.0% 掉到 66.7%，因為藍席拿的是同一支碼、攻城變兇（`rule·rule` 破網率 16.7% → 37.5%）。這不代表完全查無跡象：訓練日誌在輪邊界印了「舊冠軍重新評分 60.39 → 0.00」，看板的「固定參考尺」也確實跟著動——但**那條線不能當偵測器**，實測防守席各輪的 `rule` 基準是 78.40／63.66／67.03／93.61／75.72（每輪只量 8 場），抽樣波動比批次四那 +3.0 分的真實位移還大，而看板的時間軸與履歷也不會出現任何接縫虛線。所以跨這一天比分數要自己標「不可比」。這是**已知落差**，不是已解決的事：要讓它自動浮現，得把 `js/ai.js` 的內容指紋（`ai/refs/*` 已在用的那種 hash）蓋進 checkpoint／`ai/live-data.js`／履歷，在指紋改變處畫接縫並標「老師換了」——尚未實作（未列測試、未上看板）。

**v11 只改一項：`foeWall`（拆掉敵人要塞牆）現在按「開火那瞬間人在哪」計價**。動機直接來自批次五的行為改動——新計量 `foeWallNear`（開火點離敵鷹 ≤`AI_ASSAULT_RADIUS`＝56px）／`foeWallFar`（還在門外）由 arena 逐槍歸因得出，算式改成 `min(8, 近 + 0.25×遠) × 5`：貼到門口拆 8 格仍是 40 分，隔著半場啃牆 8 格只值 10 分。使用者要的順序是「先打敵車、接近主堡才打主堡」，舊尺卻對「怎麼拆的」完全不看，等於用分數把剛改掉的行為留下來。歸因鏈一路從遊戲端拉：`js/entities.js` 的 `Tank.shoot()` 把開火瞬間的車心蓋在子彈上（`b.fireX/fireY`，用開火點而不是命中點——子彈 8px/幀飛 20 幀就飄 40px，跟門檻同一個數量級），`js/map.js` 的 `bulletHit` 回傳打到的牆格，`js/game.js` 的 `recordWallHit` 記成事件，訓練端 `ai/arena.js` 逐幀清空並分類。⚠ **同一格牆一局只記一次**：道具鏟子（`shovelOn`）會把被打掉的牆補回磚塊，實測 stage 5／seed 4242 有「藍 995 幀打掉紅隊 2 格 → 1364 幀鏟子還原」的一例，不去重就能「拆—長—再拆」反覆領同一筆分；也是同一個原因，`foeWallNear + foeWallFar` 跟舊的 `foeWallLost`（結算時還少幾格）**可以不相等**，兩個問的是不同的事（`node audit-walls.js 5 4242` 印的是整條因果）。`breach`（70）／`penetration`／`besiege` 沒動，兩套標準的項數仍是進攻 23／防守 22。

- ⚠ **這不等於激烈度變好了**——那是新尺的分數，跨版不可比；激烈度驗收照 §5.9.7 那條規則等**兩個段邊界（≥40 代）之後**、兩席都是 v13 自己訓出來的冠軍，再跑 `node audit-intensity.js 120` 對照 `runs/audit-intensity.v11.log`（8.8 秒／5.9 台／19.1 發），線仍是 ≥15 秒／≥9 台／≤8 發。完整的前後對照表、五份階梯並排、測試清單與踩坑記在 `BALANCE-RESEARCH.md` §5.10。

⚠ 換尺的必然副作用：**同一隻網路在新尺下會暫時變弱，測試門檻要重新量過，不能靠降標**。實測暖啟動曲線（`node runs/warm-gens.js 3 5 6`，從 `ai/seeds/seed-attack.json` 暖啟動、24 局考題）在第 3 代只有 7/24 勝、7/24 破局（舊尺下同一題是 19/24），到**第 5 代**才是 24/24 勝、適應度 200.80——所以 `test-train.js` 的暖啟動那一節把代數從 3 提到 **5**、門檻（勝率 ≥40%、進攻破局 ≥50%）不變。⚠ 但「3 代不夠」這件事**不要讀成「v12 學得比較慢」**：同一支探針在 v11 的乾淨舊碼樹（`git worktree add runs/_v11wt HEAD`）上做了配對 A/B（同種子、族群 8、同 24 局考題），兩把尺讀到幾乎鏡像的曲線——v11 是 3 代 23/24、5 代 10/24，v12 是 3 代 7/24、5 代 24/24，也就是這個預算下暖啟動探針分不出「尺的效應」與「世代噪音」（完整表格與判讀見 `BALANCE-RESEARCH.md` §5.9.4；真正的激烈度驗收因此押在成熟冠軍那組 120 局上，見上一節）。另一處是 `U` 節的考績校驗把 `maxFrames` 從 1500 提到 1900：1500 幀會把「先混戰再破局」的新行為截斷，截斷那一局 `end = null`，記帳就出現 `{"?":1}`；1900 大於規則上限 1890 幀，才是真的在驗記帳、而不是驗截斷。

⚠ **v11 這一版是「老師與尺同時換」**：批次五動了 `js/ai.js`（選靶與 `_goal`），又動了算式，所以 v10 前後的分數不可直接比，而 `SCORING_VERSION` 只能標出「換尺」那一半——「換老師」那半仍然要靠上面說的指紋接縫（尚未實作）。破局率的三段都要記（同一支 `node measure-breach.js 120`、各 120 局隨機地圖）：**批次四 33.3% → 批次五初版（把「先打敵車」寫成位移去追車）22.5% → 收斂後（位移只認主堡、打車交給選靶）29.2%**。中間那一跌不是「先打敵車」的必然代價，是把它放錯層的代價：五種追車範圍在同一組 240 局考題上並排（`node audit-hunt.js 240`）讀 18.3%／18.3%／20.4%／**31.7%**，標準誤差 ±3.2%——「縮小範圍」根本救不動，只有不追才回得來（完整證據鏈與六項驗收指標的三點對照見 `BALANCE-RESEARCH.md` §5.8）。防守席的移動目標一條都沒改（`node audit-goals.js` 驗證紅隊在敵半場的那些幀全部來自 defend／hold／duel，`hunt`／`assault` 一幀都沒有），而訓練端往門口推的訊號還在 `breach`／`besiege`／v11 的近距離拆牆那三項上。

匯出檔與履歷都帶 `scoringVersion`，續練時 `ai/evolve.js` 偵測到版本不符會把舊冠軍在**現行的尺**下重評一次，並在時間軸標「換版」。⚠ 存檔檔名裡的 `v6`（`runs/attack-v6.json`／`runs/defense-v6.json`）是這一對存檔**開族時的標籤**，不是算分版本；升版不換檔名，換檔名等於把已經練好的幾百代丟在原地沒人接。真正的版本在檔案內的 `scoringVersion`。

### 雙族群：進攻模型與防守模型分開練

「藍進攻、紅防守」之後，一個族群不可能同時把兩件事都練到最好——同一份網路被兩種角色輪流考，分數永遠是兩邊的平均。所以訓練端拆成兩族：

```bash
node ai/split.js                       # 第一次：從舊的單模型冠軍拆出進攻族＋防守族兩份存檔
node ai/auto-train.js                  # 之後交替演化（auto.bat 就是這條）
```

`ai/auto-train.js` 每一輪做兩段：**進攻族練 N 代**（對手＝防守族最新的冠軍）→ 匯出 → **防守族練 N 代**（對手＝剛匯出的進攻族新冠軍）。兩族互為考題，一邊變強另一邊的尺跟著變嚴，這就是交替自我對弈。各自一份 checkpoint（`runs/attack-v6.json`／`runs/defense-v6.json`）、各自一份觀戰快照（`ai/trained-attack.js`／`ai/trained-defense.js`），絕不共用。

觀戰時 `index.html` 的藍席放進攻模型、紅席放防守模型（右欄 ③「上場的模型」可切：雙模型對打／同網自我對弈／藍網路・紅規則／藍規則・紅網路）。即時看板 `ai/live.html` 一次只反映**正在練的那一族**，角色會隨段切換；要看兩族的歷史請開 `ai/ledger.html`（`node ai/ledger.js --all` 產生，同時列兩族）。

### 全自動模式（雙擊 `auto.bat`，之後不用手動匯出、不用按鍵）

使用者的要求原話：「我要自動遊戲自動訓練 不要有手動處理」。這條路把整條產線接起來：

```bash
node ai/auto-train.js             # 無限輪，每輪「進攻族 20 代 → 防守族 20 代」自動接續
node ai/auto-train.js --gens 10   # 每段改 10 代
node ai/auto-train.js --once      # 只跑一輪就停（測試／有事要關機）
node ai/auto-train.js --mode rule # 觀戰改成「藍＝進攻網路、紅＝規則 AI」（預設 dual＝兩席各自的角色模型）
node ai/auto-train.js --stage 2   # 看地圖索引 2（STAGE 顯示 3）
node ai/auto-train.js --no-open   # 不自動開瀏覽器
node ai/auto-train.js --off       # 停用「開頁面自動觀戰」（刪 ai/auto-watch.js）
```

⚠ 從 agent 的 shell 重啟時踩到的環境坑（2026-11-04 實測，一般使用者不受影響、照舊雙擊 `auto.bat`）：`cmd //c start "…" auto.bat` 在這台機器**開不出新主控台**——命令卡住、進程根本沒起來（用 `start "" cmd /c "echo hello>檔案"` 的最小實驗證實）。能用的是 `node runs/_launch-trainer.js`：它用 Node 的 `spawn(process.execPath, ['ai/auto-train.js'], {detached: true, windowsHide: true})` 把訓練從本終端脫離。脫離之後沒有視窗可按 Ctrl+C，停止要用 `taskkill //PID <runs/auto-train.lock 裡的 pid> //T //F`（存檔是 tmp+rename，最多損失「當前這一代」）；⚠ `--off` 只清自動開場旗標、**不會停訓練**，也沒有 `--stop` 這一顆。

它做五件事：

1. **兩族交替訓練**：子程序跑 `ai/evolve.js --resume runs/attack-v6.json`（或 `defense-v6.json`）`--gens N --save-every 1 --export-to ai/trained-<角色>.json --export-every 1`，進攻段結束立刻接防守段，對手取另一族最新的冠軍快照。
2. **每代刷新兩份快照**：`ai/trained-attack.js`／`ai/trained-defense.js` 各自每代更新，瀏覽器每 12 秒重讀；代數、匯出時間自己動，任一族的冠軍換人時**場上該隊**的車直接換 policy。
3. **自動開場**：寫出 `ai/auto-watch.js` 旗標（內含兩份快照檔名，藍席放進攻、紅席放防守），`index.html` 一打開就自己進觀戰，不必在標題畫面按 Y／U。想自己玩時，在觀戰結束畫面按 Enter 回標題即可（自動開場只在載入頁面時觸發一次）。
4. **第一次開機也零手動**：兩份 v6 存檔若不存在，先自己跑 `node ai/split.js` 從舊的單模型冠軍拆出兩族。
5. **掛掉自動重開**：子程序非零結束會在 5 秒後重試（退避最多 60 秒）；只有 Ctrl+C 會真的停，並把旗標刪掉（下次開頁面回標題）。

進度看兩處：`runs/trainer.log`（訓練原始輸出，每段一個標頭、掛掉的原因也在這）、`ai/live.html`（即時看板，一次顯示正在練的那一族，角色與代數每代更新）。鎖檔 `runs/auto-train.lock` 會擋掉重複啟動；啟動時也會檢查 `ai/live-data.js`，若還有另一支訓練在跑（`running=true` 且兩分鐘內有更新、而且寫的不是這兩份存檔）就拒絕，避免兩支程序互相蓋存檔。

⚠ 第一次使用這個版本時，**已經開著的舊分頁要重新整理一次**（頁面上的舊 JS 不會自己換成有自動跟隨的版本）；之後就不用了。`train.bat` 仍然保留給「只跑固定幾代、不要無限接續」的情境。

### 邊看邊練（同時觀戰與訓練）

訓練是純 Node 的無頭模擬，觀戰是瀏覽器裡的獨立程序，兩者互不干擾：**可以一邊開著 `index.html` 看舊快照、一邊在另一個終端機訓練**。觀戰頁每 12 秒自動重讀 `ai/trained-attack.js`／`ai/trained-defense.js`：訓練若只加 `--export-to`（預設在結束時匯出），就等練完換一次；加上 `--export-every 1`（`ai/auto-train.js` 與 `train.bat` 的預設）就會每代跟著換。

最省事：雙擊 `auto.bat`（全自動、兩族交替、無限輪）。`train.bat` 留給「只跑固定幾代、不要無限接續」的情境，它等於下面這條：

```bash
node ai/train-cli.js                 # 進攻族 runs/attack-v6.json，20 代

node ai/train-cli.js defense         # 換防守族（runs/defense-v6.json）
node ai/train-cli.js defense 10      # 防守族只跑 10 代
node ai/train-cli.js 40 runs/neat.json   # 指定存檔（角色從檔名認）
# 參數不拘順序：角色 / 代數 / 存檔路徑 各認各的
```

⚠ 只練一族時，對手取**另一族最新的冠軍快照**（`--vs ai/trained-defense.json`，拿不到才退回規則 AI），所以分數仍舊可比；但「一邊變強另一邊的尺跟著變嚴」的交替不會自己發生，那是 `auto.bat` 的事。同一份存檔**不要同時開兩個訓練程序**。

訓練中另開一個終端機視窗確認「有沒有在跑」，看三件事就夠：

```bash
node ai/evolve.js --status runs/warm-v2.json
```

- **每代一行**：終端機會印 `gen 101  best=124.98  mean=79.90  species=1  …  16.5s`，有新行就是活著。
- **`--status` 的「最後落盤幾秒前」**：每 2 代落一次盤（約 30～40 秒），這個數字會週期性歸零。超過 3 分鐘沒更新且你沒按 Ctrl+C，就是那支 node 結束或掛了（看 `runs/*.log` 最後幾行）。
- **履歷的工作階段**：`node ai/ledger.js --ckpt runs/warm-v2.json` 會多出「第 N 段、幾代幾場幾分鐘」。

兩件事不要做：同一份存檔**不要同時開兩個訓練程序**接（會互相覆寫，最後一段的紀錄會亂；自動模式有鎖會幫忙擋）；也**不要**期待光開著觀戰頁就會變聰明——頁面會被動跟隨新快照，但訓練本身只在 Node 端發生。

### 即時訓練看板（`ai/live.html`）

「隨時打開就能看到現在跑到哪」：雙擊 `ai/live.html`，不需要伺服器。它每 3 秒重讀同目錄的 `ai/live-data.js`，顯示目前世代、歷史最佳、本代平均、累計場數、冠軍停滯代數、本段進度與預估剩餘時間、考題設定、實戰考績、最近世代與歷次工作階段；收斂曲線把「換圖」「換算分版本」「換對手」「工作階段開始」畫成不同顏色的虛線，接縫前後不假裝可比。

⚠ **「換對手」只標代表**：交替演化每段都換一次對手，3,000 代看全部時有 150 條這種接縫，全寫上字就變成一牆「換對手」把曲線壓住（2026-11-02 用無頭 Chrome 截圖才看出來——`node runs/tmp-dashboard-check.js` 那種「跑完不拋錯」的驗證看不見長相）。所以只挑幾條代表寫字（上限＝繪圖寬度÷240px），其餘淡虛線照畫、位置不丟，滑鼠移上去仍有提示，標題同時註明「另有 N 條未標字」。它的顏色是桃紅 `#e075c8`，**不是**紫色——紫色留給「凍結快照」那條參考線，兩件事共用一個顏色時圖上分不清哪條是尺、哪條是換尺。

**「它到底有沒有變強」靠兩把不進適應度的參考尺回答**（`node ai/evolve.js --ref ai/refs/reference-xxx.json`；沒給 `--ref` 時 `ai/evolve.js` 會自動去 `ai/refs/reference-對面席位.json` 找那把凍結尺，全自動訓練就這樣帶動它，`--no-ref` 才是關掉）：一把是遊戲內建規則 AI（最軟的基準），一把是**凍結的對手機快照**（`ai/refs/` 下的檔案內容永不更新，只讀不寫）。每代拿同一批個體去打固定的 8 場考題，數字掛在看板下方的「固定參考尺」區塊，並以虛線疊在同一張收斂曲線上。判讀方式：活對手（對面那族的新冠軍）每段都在變，所以主曲線跳一格可能只是**換尺**；如果那兩條虛線同向移動，才是真的變強或變弱。逐代紀錄另外有「原始分」（封頂之前的平均加總）與「0 分占比」兩欄，用來看還沒被地板壓住的水位——不然「最佳平在 0」在圖上跟真的停滯長得一模一樣。

```bash
# 1) 正常訓練：ai/evolve.js 每代自動覆寫 live-data.js（推薦）
node ai/evolve.js --resume runs/warm-v2.json --gens 20

# 2) 訓練已經在跑、來不及重開：另開一個終端機監看 checkpoint
node ai/live.js --watch runs/warm-v2.json

# 只寫一次快照（不監看）
node ai/live.js --once runs/warm-v2.json
```

- 資料檔是 `window.__LIVE__ = {...}` 的 **JS**，不是 JSON：`file://` 下瀏覽器擋 `fetch()` 讀本機檔，但 `<script src>` 可以。網頁用帶 cache-buster 的 script 重載，所以開著就會自己更新，不必手動 F5。
- 看板**只做摘要**：不重算適應度、不跑模擬，所有數字照抄 checkpoint／訓練程序的記憶體，不會出現「看板算一套、訓練算另一套」。
- 訓練程序自己寫的那份，`running` 是確定的布林值；正常結束或 Ctrl+C 都會寫成「已停止」。`--watch` 只看得到「檔案有變」，分不清訓練是否還活著，所以狀態顯示「檔案監看」；超過 3 分鐘沒動會提示可能已停止。
- 測試跑 `ai/evolve.js` 時會自動加 `--no-live`，不會覆寫你正在看的看板資料。

### 續練時加入沒練過的地圖

`--resume` 預設沿用存檔裡的考題；要換圖必須**明確**打 `--stages`（不然接續時會被 CLI 的預設 `0,1` 悄悄蓋掉上一輪的設定）：

```bash
# 原本只練過 0,1；把沒練過的 2,3 一起加進來，從第 141 代接著跑
node ai/evolve.js --resume runs/warm-v2.json --stages 0,1,2,3 --gens 40 --export-to ai/trained.json
```

換圖就是換一把尺，所以工具會做三件事：

- **舊冠軍先在新考題重評**（實測：同一個網路在 2 圖考題 124.98，換到 4 圖 + v3 後是 108.90）。不重評的話，舊分母會壓著新世代，或造成「第一代就破紀錄」的假象。這次重評的校準局不計入訓練場數。
- **算分換版也會重評**：v2 → v3 同樣是換尺（新增防守／協同兩項加分）。即使沒打 `--stages`，續練時只要發現存檔的冠軍是舊版算分，也會先重評一次並在履歷標「換版」。
- 該段工作階段記下 `examBefore` 與 `championRescore`；履歷時間軸會標「換圖」，收斂曲線在接縫處畫虛線——**接縫前後的 best／mean 不可直接比**。
- 每代成本＝族群 × 地圖數 × 種子數 × 2。從 2 圖加到 4 圖約變兩倍（實測每代 16 秒 → 33 秒左右），跑之前先抓一下時間。

地圖索引現在是 `0..254`（`js/constants.js` 的 `MAP_VARIANTS = 255` 張**隨機生成**的地形，地形由 `js/mapgen.js` 依編號固定產生）；超出範圍的 id（例如 300）會在載入存檔前就被拒絕，不會污染 checkpoint。

先跑過 `--export` 或 `--export-to`，打開 `index.html`，在標題畫面按 `Y`（訓練 AI 對規則 AI）或 `U`（自我對弈）。左側「訓練 A.I.」面板四行各是：快照代數、快照適應度＋觀測欄數、匯出時間、本機已觀戰場數；滑鼠停在上面會展開訓練時間軸與「要讓它變聰明該跑哪一條指令」。載入失敗或規格不符時該區會變紅並寫原因。

網址列也支援：`index.html#watch=both&stage=7`（`file://` 下查詢參數與 hash 常被剝掉，Qoder 內建瀏覽器兩種都會被剝，所以按鍵 `Y`／`U` 才是通用路）。

### 過程監測網頁（`ai/monitor.html`）

「最後誰贏」看不出訓練好不好——一台貼著牆掃射、從不機動的坦克照樣能贏規則 AI。所以監測量的是**過程**：`ai/telemetry.js` 在每一幀記下每台被網路控制的坦克按了什麼、動了沒有、子彈死在哪、走過哪些格子，再用 10 條紅旗把「結論好看但過程是壞的」打法抓出來。

```bash
node ai/monitor.js --ckpt runs/warm.json --stage 0 --games 4    # 產出 ai/monitor-data.js
# 再開 ai/monitor.html（`file://` 直接開，資料是 JS 賦值檔，同樣不需要伺服器）

# 橫向比較：把種子、冷開機、暖啟動三份檔丟同一次執行
node ai/monitor.js --ckpt runs/seed.json,runs/cold-v2.json,runs/warm-v2.json --stage 0 --games 4
```

`--ckpt` 接受三種檔：訓練 checkpoint、`--export` 的基因組檔、`ai/imitate.js` 的模仿種子（觀察規格不符的一律拒絕，並在網頁上寫原因）。頁面把資料分成兩塊：**結論面**（勝率、網路控制權、平均幀數、是否打到上限沒結果、適應度／模仿忠實度）與**過程面**（五個動作的使用分佈、卡牆比例、卡牆時還在開火的比例、子彈都打在哪、18×42 熱點地圖（直式長場，寬高分開算）、逐局數據表）。熱點地圖可以切「全部累積／第 N 局」與「訓練網路／規則 AI」，也能同時並排多份 checkpoint 橫向比較（例：模仿種子／冷開機 60 代／暖啟動 80 代）；每張紅旗卡片都附了實測值、門檻、為什麼是壞事、以及下一輪該怎麼修。

紅旗清單（`ai/telemetry.js` 的 `RULES`）：動作單一（>80%）、從不後撤（上下某向 <0.5%）、卡牆開火（擋住 >25% 且其中開火 >10%）、對打不動的目標開火（>15%）、幾乎不破牆、不推進（整局 <16px）、其實是規則 AI 在開（abstain >50%）、送頭（死 6 次以上且 K/D <0.7）、拆自己家（>0 發）。

### 訓練履歷（`ai/ledger.js`）

監觀看「這一輪怎麼打」，觀戰看「這一場怎麼打」，履歷回答另外兩個問題：**牠到底被訓練過幾次**、**牠是被什麼標準評出來的**。

```bash
node ai/ledger.js --ckpt runs/warm-v2.json      # 文字版履歷（含歷練時間軸）
node ai/ledger.js --all                         # 掃 runs/ 與 ai/trained.json 一次看完
node ai/ledger.js --rubric                      # 只印評判標準（進攻 24 項／防守 23 項計分＋10 條紅旗＋12 條協議）
node ai/ledger.js --verify runs/warm-v2.json    # 用沒參與評估的新種子實戰一輪，考績寫回檔案
node ai/ledger.js --ckpt runs/warm-v2.json --breakdown   # 拆一局給你看各項貢獻怎麼加總
```

三個設計點：

- **標準與算分出自同一支碼**。履歷上的每一項權重、算式、上限都是 `ai/fitness.js` 的 `TERMS`——就是演化時真正在用的那份，不是另外寫的說明文件。`rubric()` 還會檢查「有權重卻沒進 `TERMS`」並報出來，避免展示給人的標準偷偷少一項。
- **舊存檔不編故事**。`sessions` 記錄是這輪才加上的，之前的存檔只能從 `neat.history`／`episodes` 反推，履歷會把那段標成「推導」而不是假裝有時間軸。
- **考題與考績分開**。訓練時評估用的種子（salt `0x5eed`）跟 `--verify` 用的種子（salt `0xc0ffee`）是兩把，否則「勝率」量的是背題不是會打；考績結果連同基因指紋一起寫回檔案，可以看到同一隻網路歷次考核的變化。

`--breakdown` 的輸出長這樣（實測：暖啟動 100 代冠軍、關卡 0、考績那把種子的一局，549 幀取勝）：

```
▍實例拆解：runs/warm-v2.json 在關卡 0 打一局（549 幀，網路（藍）勝）
     在場 597 幀｜擊殺 0｜陣亡 1｜開火 28 發（造成 0 hp）｜卡牆 0%｜家門口攔截 0 hp／0 殺｜協同 0.0%
       +60.0  贏得本局      ｜1.000 × 60
       +22.0  打掉敵方老鷹  ｜1.000 × 22
       +14.0  守住自家老鷹  ｜1.000 × 14
        -4.0  損失一台車    ｜1.000 × -4
       +11.2  贏得快        ｜0.931 × 12
        -7.4  動作單一      ｜0.210 × -35
     合計 95.82
```

每一項都印出「乘上權重之前的量 × 權重」，所以標準表跟實際分數對不對得上，一眼就能查。這一局也順帶暴露了實情：牠贏是靠直攻敵方老鷹，28 發子彈對坦克造成 0 hp 傷害、動作分佈仍偏單一——這種事只看「勝率 75%」是看不出來的。


1. **一局必須可重現**：`(地圖, 種子, 控制器組合)` 完全決定結果。`ai/arena.js` 用 `vm` 沙盒載入**真正的遊戲碼**（DOM、canvas、`localStorage`、`requestAnimationFrame` 全打樁），關掉渲染、逐幀呼叫遊戲自己的 `update()`，所以訓練場裡的行為跟瀏覽器裡看到的是同一套實作，不會「訓練用一套、執行用另一套」。
2. **適應度要逐幀歸一化**：一局 600 幀和一局 3000 幀不能直接比誰殺得多。流量型計量（擊殺、傷害、開火、撿道具）一律換算成「每 1000 在場幀」，在場幀再扣掉出生無敵與被凍結，避免「活著不動」刷分。
3. **觀測規格不能改**：`ai/observation.js` 的 `OBS_SPEC`（目前 v2、85 欄；v2 比 v1 多 5 欄「前後左右是否被擋＋當前朝向」）一旦定稿，改欄位等於作廢所有既有基因組。checkpoint 記錄規格版本，載入時不符會直接失敗並說明原因，而不是靜默重訓——實測拿 v1（80 欄）的舊種子暖啟動會被擋下。

**反刷分設計**：亂槍掃射由「每發子彈造成的 hp 損失」封頂；整局躺平直接歸零；拖到幀上限沒結果 −18；把自己老鷹打掉的分數**封頂在「守住老鷹」的固定分之下**（次序絕對正確），但不歸零——早期個個被拆家，全部 0 分就沒有選壓、演化會停滯。

**過程也計分**：只看結論會練出「勝率很高但整局貼著牆掃射」的退化冠軍，所以紅旗指標直接進適應度——卡牆比例（>20% 起扣、60% 扣滿，最多 −40）、動作單一（最常用的那個動作佔比 >60% 起扣、100% 扣滿，最多 −35）、大量子彈打在零傷害目標上（−12）、開槍打到自己家（每發 −7）。懲罰是**連續梯度**而不是階梯，讓演化有方向可循；沒有 policy 的隊伍（純規則 AI）不受這些懲罰誤傷。

**防守與合作有自己的分（v3，v5 擴大）**：v2 以前只看「打了多少、最後守住沒有」，速攻型的個體幾乎不需要回防，所以防守與合作從來沒有梯度。v3 起另計加分，v5 再把「打擊對方坦克也是防守」補進來：

- **家門口攔截**：敵車在自家老鷹 56px（約 7 格）內挨的傷害，每 hp × 5、上限 6 hp（最多 +30）。
- **半場攔截（v5）**：敵車踏進自家半場、但還不在 56px 家門口內時挨的傷害，每 hp × 2.5、上限 8 hp（最多 +20）。兩個區段互斥，同一筆傷害不會重複計價；家門口更關鍵，所以單價較高。
- **協同壓制**：同一隊兩台以上在場車同時貼著同一台敵車的幀占比，10% 起算、25% 滿（最多 +10）。規則 AI 對規則 AI 的 baseline 約 3%～13%，所以門檻設在 10%，避免把「剛好同框」當合作。

三項都是加分項，喜歡單打或速攻的個體不會被扣分。換版一樣是換尺：同一隻網路在 v3 會多拿一點（實測 124.98 → 125.14）；v5 同時改了移動規則，舊分數不能直接比，續練時會自動重評舊冠軍並在履歷標「換版」，校準局不計入訓練場數。

### 座位公平（不修正就會練出「假聰明」）

NEAT 會把任何系統性偏置放大成高分。四處偏置先拿掉，否則分數量到的是位子而不是智力：

- **地圖**：上下 180° 點對稱（`cells[y][x] === cells[25-y][25-x]`）。
- **出兵節奏**：兩隊首發同幀（原本紅隊晚 25 幀出兵）。
- **同幀結算順序**：每幀隨機翻轉 `tanks` 的處理順序。原本固定藍先紅後，讓所有「同幀互毀」都由藍隊獲勝（藍的子彈先進陣列、先結算），實測 200 局藍隊 58.5% 勝率；修正後 200 局 100:100。
- **評估方式**：每個基因組在同一組 `(地圖, 種子)` 下藍紅各坐一次取平均，殘留的統計偏置不會被誤判成較聰明。

### 實測成果：暖啟動 vs 從零訓練（2 圖時期）

`ai/trained-attack.js`／`ai/trained-defense.js` 是訓練成果的快照（v6 之前只有一份 `ai/trained.js`），全自動訓練每代刷新、頁面每 12 秒自動跟隨。2026-10-31 晚上切到 v5 時，舊冠軍（第 275 代）先在新尺上重評 114.33 → 96.57；續練幾代後就出現 121.80 的新冠軍（第 356 代，v5）。下面這張表是更早的 2 圖考題、v1/v2 計分時期的對照，用來回答「暖啟動到底買到什麼」；表裡的 118.9 是同一隻在舊尺上的數字，不能跟 v5 的分數直接比。兩邊都是族群 24、關卡 0/1、每代 2 種子 × 雙座位。

| 代 | 冷開機 best | 冷開機 mean | 暖啟動 best | 暖啟動 mean |
| --- | --- | --- | --- | --- |
| 1 | 86.3 | 9.3 | 90.6 | **40.2** |
| 5 | 86.3 | 56.2 | 90.6 | 36.0 |
| 10 | 94.0 | 59.3 | 104.7 | 50.4 |
| 20 | 107.3 | 57.5 | 113.4 | 71.1 |
| 40 | 111.6 | 75.0 | 113.4 | 59.8 |
| 60 | 116.8 | 76.2 | 113.4 | 67.4 |
| 80 | — | — | **118.9** | 65.2 |

實戰（關卡 0/1/2 × 4 個**沒參與評估的新種子** × 雙座位＝24 局，對手都是規則 AI）：

| 對象 | 勝率 | 控制權 | 卡牆 | 每擊殺耗彈 |
| --- | --- | --- | --- | --- |
| 模仿種子（第 0 代，未演化） | 11/24 = 46% | 100% | 0.0% | **2.7** |
| 冷開機第 60 代冠軍 | **23/24 = 96%** | 100% | 0.0% | 31.9 |
| 暖啟動第 80 代冠軍 | 19/24 = 79% | 100% | 0.1% | 25.7 |

**誠實的結論：暖啟動買到的不是「更強的最終冠軍」，而是「合理的起點」。** 它讓第一代的平均適應度從 9.3 跳到 40.2，一開場就躲掉「整代都在學會不會動」的空轉期；種子的射擊精準度（2.7 發一殺）也是演化之後的兩份網路都比不上的。但在這組設定下，冷開機最後的勝率反而比較高——它的代價是每擊殺要砸 32 發子彈的掃射式打法（因為卡牆 0%、動作分佈也沒退化，所以沒有踩進紅旗門檻）。兩份網路的 `best` 在 40 代之後都進入高原、物種數固定在 1（相容性閾值對這個族群大小偏鬆）。

要在勝率上真正拉開，下一步是 `--opponent best` 自我對弈（對手不再是被模仿對象本身）、加大 `--pop`、放寬 `--stages`；要讓「準確但不贏」的種子特性留下來，則是把每發子彈的 hp 產出也放進適應度權重（見 `ai/fitness.js` 的 `W`）。

**2026-10-31 四圖續練（誠實版）**：從第 141 代接續，把地圖 0,1,2,3 加進考題、算分升到 v3，又跑了 40 代 15,360 場（20 分 25 秒）。舊冠軍在換圖時重評 124.98 → 108.90；這 40 代內沒有任何個體超過它，每代平均在 54～78 之間盤旋，物種數仍是 1。實戰考績（4 圖 × 4 個沒參與評估的新種子 × 2 座位＝32 局）是 **26/32 = 81%**、控制權 100%、卡牆 0%、每擊殺 24.5 發。結論：四圖沒有把冠軍練得更強，但把「只在兩張圖有效」這件事暴露出來，而且新地圖上的實戰仍有 81%。下一步該動的是對手（`--opponent best`）與族群多樣性（提高相容性閾值或 `--pop`），不是再跑幾代同樣設定。即時看板 `ai/live.html` 與履歷 `ai/ledger.html` 都保留這段換圖接縫，不會把前後的 best／mean 混在一起比。

- **最小字級 16px（使用者規則）**：頁面（`index.html` 的左右欄、`ai/live.html`、`ai/ledger.html`、`ai/monitor.html`）所有文字 ≥16px，層次靠 17／18／19／20／30px 拉，不靠縮字。代價是版面要跟著改：側欄 230px → 320px 並允許 `flex-wrap`（視窗太窄時面板掉到畫布下方，而不是把數字截掉）、看板的 tile/表格最小寬度放大、圖表留白加大、x 軸刻度改 4 格。
- **畫布上的字是「邏輯 px」**：`js/renderer.js` 的字級到螢幕要乘 `SCALE = 2`，所以地板設在 9（＝18 CSS px）、HUD 用 10（＝20 CSS px）。三張圖表（`live.html`／`ledger.html` 的 canvas、`monitor.html` 的 SVG）一律把座標系設成 1 單位＝1 CSS px，否則 `viewBox` 縮放會把 16 變成小於 16。
- **圖表接縫標籤會搶地盤**：交替演化每段都換對手＝每段一條接縫，800 代看全部時有三十多條、間距不到 40px。做法是虛線全畫（位置不能丟）、文字用矩形佔位 greedy 挑著標（換圖／算分換版優先卡位，純「換對手」只填空檔），放不下的就不寫字；每個標籤再描一圈底色當光環，壓到曲線也讀得出來。
- **座標系統**：1 子格 = 8px，戰場 18×42 格（9:21 直立長場）= 144×336 邏輯 px，坦克 16×16。畫布 288×672（`SCALE = 2`），頁面再用 CSS 依視窗高度放大（`height: clamp(672px, calc(100vh - 130px), 1344px)`）——**位圖不放大**，否則貼圖會糊（`SPRITE_SS` 維持 2，畫布尺寸的變化全部交給 CSS）。
- **貼圖解析度**：所有貼圖以 `SPRITE_SS = 2` 的細節解析度繪製（磚塊 16×16、坦克 32×32、大爆炸 64×64），渲染時縮回邏輯尺寸，使 1 個美術像素正好等於 1 個裝置像素。
- **移動手感**：轉向時垂直軸自動吸附到最近格線，前進只改方向軸座標，因此不會漂移、不會卡牆。
- **迴圈**：`requestAnimationFrame` + 固定 60fps timestep 累加器，邏輯更新與渲染分離。
- **音效**：方波/鋸齒波/三角波與雜訊緩衝合成，`AudioContext` 延遲建立並在需要時 `resume`（瀏覽器首次互動後才會發聲）。

## 測試

無瀏覽器依賴的回歸測試，直接在 Node 執行（需要 Node 16 以上）：

```bash
node test-harness.js     # 遊戲本身與規則層：187 passed, 0 failed
node test-neat.js        # NEAT 不變量：44 passed, 0 failed
node test-train.js       # 訓練管線：311 passed, 0 failed
```

三套也由 `.github/workflows/ci.yml` 在每次 push／PR 自動跑一遍（純 Node，`ubuntu-latest` 上約一到兩分鐘，不需要 `npm install`），最後一步還會檢查 `ai/trained-attack.json`／`ai/trained-defense.json` 解不解得開、席位與算分版本跟現行碼對不對得上——防的是「訓練端匯出寫到一半，結果把半成品快照推到線上」。

⚠ CI 那台機器是全新 clone，**沒有 `runs/`**（`.gitignore` 把整個目錄排除，因為 checkpoint 隨代數一直長大）。`test-train.js` 暖啟動那一節要模仿種子，它先找 `runs/seed-<席位>.json`，找不到就退回版控裡的定格副本 `ai/seeds/seed-<席位>.json`。重記種子之後（老師 AI 一動種子就過期，見「種子會過期」那段）記得把新檔蓋進 `ai/seeds/`，否則 CI 驗的是舊種子、跟本機不同檔。

### `test-harness.js` — 遊戲規則

測試用 `vm` 建立沙盒，把 DOM、`canvas`、`localStorage`、`requestAnimationFrame` 打樁，然後**載入真正的遊戲碼**，透過驅動真實幀與鍵盤事件來驗證行為，而不是測試重寫過的邏輯。

涵蓋範圍：

- **單人＋觀戰基礎 35 項**：狀態流轉（標題 → 進場 → 進行中 → 暫停 → 過關 → 結束）、磚牆 1/4 格削除、轉向格線吸附、基地阻擋與被擊毀、冰面滑行與離冰即停、鏟子鋼牆還原、出生點被佔時不出生、擊殺計分與敵軍圖示遞減、閃紅掉道具、2 萬分獎命、炸彈全滅、星星升火力與子彈加速、玩家死亡重生與火力歸零、`T` 進入觀戰、雙基地位於上下、兩隊出生點淨空、開局中央點對稱出生、觀戰頁啟用中央開局（訓練端維持四點）、無人類玩家坦克、兩隊都實際派車、隊伍標記一致、坦克池遞減、HUD 同步兩側數量、一輪能分出結果且確實發生交戰、自動開下一輪、`Enter` 回標題後單人狀態完整復原、900／1200 幀實戰 soak。
- **隨機地形不變量 51 項（v9 新增）**：對抽樣的地圖編號（0..23 加上 100／199／250／254）逐張檢查——老鷹與要塞磚環完整（開路絕不可挖的地方）、八個出生點淨空、**每一格都滿足 180° 點對稱**（`cells[41-y][17-x] === cells[y][x]`，兩隊家門口的地形幾何完全等價）、兩隊**從出生tile走到敵方要塞外側那一排**都真的有路（tile 級 BFS，挖 1 cell 寬的假隧道不算）、原始 tile 展開的 cell 對齊、地磚密度落在 8%～55%、同編號必定重現、不同編號長得不一樣、編號環繞（255→0、-1→254、300→45）、單人／觀戰的基地座數、`9:21` 幾何與 `MAX_SCAN_CELLS`。這裡有兩條是**真的抓出 bug** 才留下來的：`_ensureRoutes` 以前只挖「藍→紅」那條路，結果地圖不再點對稱、紅隊連一條保證能攻進去的路都沒有。
- **每輪隨機抽圖 10 項**：連續 8 輪都落在 `0..MAP_VARIANTS-1` 之內且不只抽到同一張、抽到的編號與實際地形一致（`map.mapId === demoStageIndex`）、`R` 鍵重開本輪沿用**同一張**圖（不然「重看剛剛那一場」會變成換圖、失去對照組）、明確指定編號時同一 stage 必然同一張圖且不會讓 `demoRound` 遞增、超出上限會環繞（258→3）、鎖圖後每一輪停在同一張且 ◀▶ 換圖時鎖一起搬過去、解鎖回覆每輪隨機、出兵組合依「編號 % `ENEMY_DIFF_CURVE`」取樣（255 張圖分散在整條難度曲線上）。
- **v6 規則與彈道 25 項**：藍進攻／紅防守的勝負判定與 30 秒倒數、時間到算紅隊贏、彈道閘（會打到自己要塞或要塞牆的那一槍不開、打一般磚牆的照開、隔著水／樹林仍不開、鏟子把牆變鋼仍算自家牆、先撞到敵家老鷹或敵隊牆就放行）。
- **v7 自破老鷹 9 項＋貼身格鬥 11 項**：自己人打爆自家老鷹要記帳（該隊該局 0 分）；中心距 < 40px 時換目標、重新決策 8 幀、冷卻 8～15 幀，且出生無敵／已陣亡的車不進格鬥名單。

### `test-neat.js` — 演化演算法的不變量

結構變異跑 4000 次，每次檢查：節點 ID 唯一、沒有懸空邊、拓撲排序涵蓋全部節點、沒有環；創新號在重複變異下穩定、分裂節點採號確定；交叉後代合法；相容性距離、快照往返（population／species／history／generation）、接續後不會長出重複邊、無輸入時 policy 正確 abstain。

### `test-train.js` — 「今天跑、明天接」真的接得回去

- **競技場**：同 `(stage, seed, 控制組合)` 逐位元組相同、換種子就會換一局、不注入時兩隊都跑規則 AI、出兵數守恆（死亡＋存活＋未出兵＝隊伍總量）、policy 只影響被注入的那一隊；半場攔截的「自家半場」依老鷹在球場哪一側判定，藍紅換邊不會判反。**v8 另驗「開場一次出滿 4 台」在訓練端也成立**（場上 4／池剩 16），而且那 4 台從第一幀就歸注入的 policy 管 —— `ai/arena.js` 與 `js/watch.js` 都必須在 `startDemo()` **之前**寫好 `teamControllerSpecs`，順序反了就會出現「面板寫著第 N 代冠軍、場上打得最久的車卻是規則 AI 替它刷分」，所以每隊各有一個 `tanksControlled` 計量釘住這件事（未注入的那一隊必須是 0）。

- **座位公平**：規則 AI 對規則 AI 60 局，藍隊勝率必須落在 40%~60%。
- **適應度**：整局拉長 3 倍但節奏不變 → 分數只小幅變動；躺平＝0 分；亂槍 < 打得準；互換命不比穩健打法高分；被拆家永遠比守住老鷹低但仍保留梯度；贏得快 > 贏得失分；拖到上限要扣分。過程懲罰另有三條要驗「壓得住退化個體」：卡牆 55% ＋只按射擊明顯低於同成績但會機動的個體、完全卡死又不殺人歸零、懲罰是連續梯度（21% < 40% < 70% 扣得一個比一個多）而不是階梯，且純規則 AI 的隊伍不受誤傷。v3 驗防守與合作：家門口攔截有加分且有 6 hp 上限、協同 10% 以下不給分且是連續梯度到 25% 封頂；v5 再驗半場攔截有加分、有 8 hp 上限，且同樣 hp 家門口比半場值錢。v10～v12 把「尺的形狀」本身變成被驗的對象：v10 那兩條結構不變量由測試釘住（本業占自己天花板 ≥40%、兩席本業上限差 ≤10——`speed` 兩席砍的幅度不同就是為了第二條），版本號那顆永遠跟著項數動（v12：進攻 24／防守 23，加一項就要動它），v12 另加八顆——殲滅每台 +6 且封在 8 台、「速決但空手」的 `speed` 歸 0、「殲滅但慢」要打得過「速決但空手」、準頭封在每發 0.8hp、彈雨的罰 −12→−30 且觸發門檻（`SPRAY_SHOTS_MIN`／`SPRAY_HP_MAX`）被釘住、通用交戰軸釘在 242（加項不長總量）、`balance.js` 的四軸分組加總要等於天花板（漏登記就會「進總分、不進軸」），最後是版本注記要寫出這一版動了哪幾項（收斂曲線那條接縫才看得懂是尺變了、不是車變弱）。

- **斷點續存**：用 `execFileSync` 真的重開一支 `node` 接回去 —— 代數連續、場數累加、innovation 計數器只增不減、同一創新號仍只對應一條邊、族群大小不變、沿用 checkpoint 的考題設定、`--episodes` 算「本次」而不是歷史累計、`--stages` 明確換考題（含不存在的關卡要在載入前拒絕、存檔不被動到）、換圖與算分換版都要重評舊冠軍且校準局不計場數、觀測規格不符與亂碼檔案都要拒絕載入、沒給上限要拒絕啟動、`--quiet` 仍遵守 `--gens`、不殘留 `.tmp`。
- **學習訊號**：6 代之後 `best` 與 `mean` 都要上升，且冷開機第一代平均水位必須仍很低（`mean < 25`）——這條是在釘住「暖啟動的對比基準」確實從零開始。
- **暖啟動**：種子對規則 AI 勝率 > 50%（考題是模仿時用過的關卡 0/1，實測 16/24）、控制權 > 90%（否則聰明是規則 AI 的）、卡牆 < 10%；`--seed-from` 寫進考題設定；暖啟動第一代 `mean` 就要有水位（> 20）；族群第 0 號保留未變異的種子（邊數與種子同級）；**5 代**冠軍坐回自己席位、對手恆為規則 AI，勝率要 ≥40%（v12 尺下實測進攻 24/24＝100%、防守 22/24＝91.7%；v13 換尺後重跑仍是 5 代、門檻沒降，讀到進攻 21/24＝87.5%（破局率也 87.5%，另一顆要求 ≥50%）、防守 22/24＝91.7%）；匯出的基因組、v1（80 欄）舊種子、`--resume` 同時給 `--seed-from` 這三種都要拒絕並講清楚原因。⚠ 這顆測試原本是「3 代」，v12 換尺後重量過曲線（第 3 代只剩 7/24、第 5 代才回到 24/24）而**把代數調高、沒有把門檻調低**——門檻一降，這顆測試就再也問不出「演化有沒有把過程變成勝負」。
- **反射層與自我傷害**：`FRONT_BASE` 索引真的落在觀測尾段；正前方是牆時反射改挑走得通的方向、四面全堵時維持原結論不亂轉；網路想原路退回時反射層會把那個方向當成走不通並改選別路，但前方撞牆時回頭路照樣放行；規則 AI 原始碼不再直接改 `tank.dir`（統一經過 `moveAsAI`）；「拆自己家」在老師／競技場／監測只有一個定義（都呼叫 `controller.js` 那份 `ownBaseInFront`）；幾何判定五種情形都要對——老鷹在槍線上＝不安全、轉個頭＝安全、敵家老鷹在槍線上＝安全（這槍有意義，不能一起攔）、中間隔磚＝安全、單人模式（沒有自家基地）不誤傷；老師取樣要驗到四類逐幀事件都收得到、「有射擊線」的樣本標籤真的是射擊、標「卡牆」的樣本確實沒移動、降權真的讓樣本變少。
- **訓練履歷**：`rubric()` 不能漏項（`WEIGHTS` 每個 key 都要有 `TERMS` 說明，且權重一致）；`explainFitness` 逐項加總要等於 `teamFitness`（展示的拆解跟實際算分是同一份碼）；`damageDone ≥ 擊殺數`（釘住「致命一擊」那個 bug）；工作階段跨 process 累加且增量是差值（第 2 段 1 代就是 1 代，不是累計 3 代）；匯出檔要帶 `provenance`／`scoringVersion`／`exportedAt` 且履歷讀得回來；沒有 `sessions` 的舊存檔要被標成「推導」而不是編時間軸；外來 `kind` 一律拒絕；`--verify` 追加考績但不動代數。
- **即時看板**：訓練端 payload 的 `running` 必須是確定的布林值；檔案監看模式必須是 `null`（不能冒充「訓練中」或「已停止」）；每代場數由 族群×地圖×種子×2 座位 算出；本段進度與換圖接縫靠 `fromGeneration`；考績會進 payload；產出必須是可直接用 `<script src>` 載入的 `window.__LIVE__` 而不是 JSON，序列化後數字與記憶體一致；CLI `--once` 與訓練端共用同一種格式。
